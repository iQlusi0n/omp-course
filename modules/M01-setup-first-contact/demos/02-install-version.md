# Demo 1.2 — Install, verify, completions, update (~40 s)

Install line is the form in the bundled docs. Everything after it is real output from `omp/18.3.1`.

```text
$ curl https://omp.sh/install | sh
  … (installer output; ends by telling you where the binary went)

$ omp --version
omp/18.3.1

$ omp completions --help
Print a shell completion script (bash, zsh, or fish)

USAGE
  $ omp completions SHELL

ARGUMENTS
  SHELL   Target shell (bash|zsh|fish)

EXAMPLES
  # zsh — eval at startup, or write to a file in $fpath
    eval "$(omp completions zsh)"
  # bash
    eval "$(omp completions bash)"
  # fish
    omp completions fish > ~/.config/fish/completions/omp.fish

$ omp completions zsh | head -2
#compdef omp
# zsh completion for omp — generated by `omp completions zsh`

$ omp completions bash | grep -c -- '--resume'
3

$ omp completions fish | grep -n -- '-l resume'
89:complete -c omp -n '__fish_omp_no_subcommand' -s r -l resume -d 'Resume a session (by ID prefix, path, or picker if omitted)' …

$ eval "$(omp completions zsh)"       # put this line in ~/.zshrc
$ omp --res<Tab>
$ omp --resume=

$ omp update --check
Current version: 18.3.1
✔ Already up to date
```

The `<Tab>` line is what you type; the line after it is what the shell fills in (zsh shows `--resume=`, bash may show `--resume`, fish shows a description column).

`omp update --help` flags worth knowing:

```text
  -f, --force    Force update
  -c, --check    Check for updates without installing
  -l, --plugins  Update installed plugins
      --canary   Switch to the canary channel and update
      --stable   Switch back to the stable channel
  # If GitHub rate-limits release metadata, set GITHUB_TOKEN or GH_TOKEN
    GITHUB_TOKEN=... omp update
```
