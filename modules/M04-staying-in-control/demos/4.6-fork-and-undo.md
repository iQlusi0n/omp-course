# Demo 4.6 — Fork before risk, undo with git (≤ 60 s)

Illustrative transcript; `/fork` semantics from omp://session-operations-export-share-fork-resume.md.

```text
$ git status
On branch main
nothing to commit, working tree clean

$ omp
> /fork
  Forked session → 2026-09-25T10-41-03-7f3a…   (new file; artifacts copied; now active)

> Rename the cancel subcommand to void across cli/ and tests, no alias.

▸ grep  "cancel" cli/ tests/
▸ edit  cli/__main__.py
▸ edit  cli/commands.py
▸ edit  tests/test_cancel.py
▸ bash  python3 -m unittest discover -s tests   … FAILED (3 errors: README examples, api client)
```

Other terminal:

```text
$ git restore .
$ git status
nothing to commit, working tree clean
```

Back in omp:

```text
> I reverted your changes with git. Re-read before editing. Do the rename but keep a deprecated `cancel` alias.

▸ read  cli/__main__.py            (fresh hashline tags — the old ones would be rejected as stale)
▸ edit  cli/__main__.py
▸ bash  python3 -m unittest discover -s tests   … OK

> /resume
  ┌ Sessions (this folder) ── Tab: all ─────────────┐
  │ ● 2026-09-25T10-41-03 Rename cancel → void       │  ← the fork
  │   2026-09-25T09-12-44 Order cancellation         │  ← original, ends before the rename prompt
  └──────────────────────────────────────────────────┘
```

While streaming, `/fork` is refused with a warning — press `Esc` first. With `--no-session` it fails (`SessionManager.fork()` requires persistence).
