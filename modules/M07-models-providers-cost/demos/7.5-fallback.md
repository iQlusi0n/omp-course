# Demo 7.5 — Fallback chain proven with `mock-provider.py --fail`          (~40 s)

Captured on `omp/18.3.1`. Primary `mock` → a mock started with `--fail` (HTTP 429, `Retry-After: 1`); `mock-backup` → a healthy mock on another port.

`~/.omp/agent/config.yml`:

```yaml
modelRoles:
  default: mock/mock-1
retry:
  fallbackChains:
    default:
      - mock-backup/mock-1
      - anthropic/claude-sonnet-4-5
```

```
$ omp config get retry.fallbackChains
{"default":["mock-backup/mock-1","anthropic/claude-sonnet-4-5"]}

$ time omp -p --mode json --no-session "say hi" | grep -E 'retry_fallback_(applied|succeeded)'
{"type":"retry_fallback_applied","from":"mock/mock-1","to":"mock-backup/mock-1","role":"default","reason":"Request failed: 429 rate limited (mock --fail) retry-after-ms=1000\nrate limited (mock --fail) (type=rate_limit_error param=rate_limited)"}
{"type":"retry_fallback_succeeded","model":"mock-backup/mock-1","role":"default"}

real    0m11.024s
```

Full event order in the JSON stream (filtered to retry/fallback types):

```
{"type": "retry_fallback_applied", "from": "mock/mock-1", "to": "mock-backup/mock-1", "role": "default", "reason": "Request failed: 429 rate limited (mock --fail) retry-after-ms=1000 …"}
{"type": "auto_retry_start", "attempt": 1, "maxAttempts": 10, "delayMs": 0, "errorMessage": "429 rate limited (mock --fail) retry-after-ms=1000 …"}
{"type": "retry_fallback_succeeded", "model": "mock-backup/mock-1", "role": "default"}
{"type": "auto_retry_end", "success": true, "attempt": 1}
```

`delayMs: 0` — a model switch never sleeps; `maxAttempts: 10` is `retry.maxRetries`. The assistant message that follows carries `"provider":"mock-backup","model":"mock-1"`.

Server logs, side by side:

