# Demo 8.3 — devices, LSP, AST codemod, semantic find (~60 s)

All blocks except "LSP rename" were captured live on `omp/18.3.1` against a throwaway copy of the lab layout (`api/orders.py`, `api/__init__.py`, `cli/main.py`, `cli/log.py`, root `pyproject.toml`). The build machine has no language server, so the rename block reproduces the output shapes documented in `omp://tools/lsp.md` and is marked as such.

## 1. What is mounted? (`read xd://`, stock session, no `--tools`)

```
> read xd://

╭─ read xd:// ─────────────────────────────────────────────────────────────╮
│ xd:// 3 mounted tool devices.                                            │
│ xd://ast_edit       Perform AST-aware code edits (structural refactoring)│
│ xd://debug          Debug a running process with DAP (debugger adapter   │
│                     protocol)                                            │
│ xd://lsp            Query LSP (language server) for diagnostics, hover   │
│                     info, and references                                 │
│                                                                          │
│ Read xd://<tool> for docs + JSON schema; write the JSON args object to   │
│ xd://<tool> to execute. Active top-level tools accept the same dispatch. │
╰──────────────────────────────────────────────────────────────────────────╯
```

## 2. LSP status with no server installed (what "not detected" looks like)

```
> Call lsp with action=status, then diagnostics for api/orders.py.

╭─ write xd://lsp {"action":"status"} ─────────────────────────────────────╮
│ No language servers configured for this project                          │
╰──────────────────────────────────────────────────────────────────────────╯
╭─ write xd://lsp {"action":"diagnostics","file":"api/orders.py"} ─────────╮
│ ✘ api/orders.py: No language server found                                │
╰──────────────────────────────────────────────────────────────────────────╯
```

Note the model reached `lsp` through `write xd://lsp` because the tool is a *device* in a stock session. With `omp --tools read,write,lsp` it would be a top-level `lsp` card instead.

## 3. LSP rename — documented output shape (NOT a live capture)

With `pyright-langserver` on PATH and `pyproject.toml` in the cwd, `lsp status` reports `Language servers: pyright (configured, not started)`. A rename then produces (per `omp://tools/lsp.md`, `rename` action):

```
╭─ lsp rename api/db.py:<def line> get_user → fetch_user (apply:false) ────╮
│ Rename preview:                                                          │
│   api/db.py: 1 edit                                                      │
│   api/__init__.py: 1 edit                                                │
│   api/server.py: N edits                                                 │
│   cli/commands.py: N edits                                               │
│   tests/test_api.py: N edits                                             │
╰──────────────────────────────────────────────────────────────────────────╯
╭─ lsp rename … (apply) ───────────────────────────────────────────────────╮
│ Applied rename:                                                          │
│   … one line per applied change …                                        │
╰──────────────────────────────────────────────────────────────────────────╯
```

Exact per-file wording comes from `formatWorkspaceEdit()` / `applyWorkspaceEdit()`; treat the file list, not the phrasing, as the pass condition.

## 5. `ast_edit` preview → `xd://resolve` → verify

```
> Use ast_edit with op pat='print($$$A)' out='logger.debug($$$A)' on paths ['cli'],
  then apply it by writing to xd://resolve, then grep for 'print(' in cli.

╭─ ast_edit 1 op · cli ────────────────────────────────────────────────────╮
│ Staged as a proposal — files NOT modified yet. To apply: write a         │
│ one-sentence reason to xd://resolve. To discard: write to xd://reject.   │
│                                                                          │
│ # cli/                                                                   │
│ ## main.py (4 replacements)                                              │
│ -5:5 print("user:", user)                                                │
│ +5:5 logger.debug("user:", user)                                         │
│ -6:5 print(f"id={user[0]}")                                              │
│ +6:5 logger.debug(f"id={user[0]}")                                       │
│ -10:9 print(r)                                                           │
│ +10:9 logger.debug(r)                                                    │
│ -11:5 print("total", len(rows))                                          │
│ +11:5 logger.debug("total", len(rows))                                   │
╰──────────────────────────────────────────────────────────────────────────╯
╭─ write xd://resolve ─────────────────────────────────────────────────────╮
│ User requested replacing all print calls in cli with logger.debug.       │
├──────────────────────────────────────────────────────────────────────────┤
│ Applied 4 replacements in 1 file.                                        │
╰──────────────────────────────────────────────────────────────────────────╯
╭─ grep print\( in cli ────────────────────────────────────────────────────╮
│ No matches found                                                         │
╰──────────────────────────────────────────────────────────────────────────╯
```

`-5:5` is `line:column` (plain mode because this run had no `edit` tool, so no hashline anchors). In a normal session the pairs are `-5:print(...)` / `+5:logger.debug(...)` under a `[cli/main.py#TAG]` header, and the apply result also prints fresh `[path#TAG]` snapshot headers.

The model's own follow-up remark is worth keeping: it pointed out that `logger.debug("total", len(rows))` now treats `"total"` as a format string — 1:1 substitution is faithful, not smart. Run the tests.
