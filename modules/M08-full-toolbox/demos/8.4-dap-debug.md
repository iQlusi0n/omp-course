# Demo 8.4 — a real debugger session on a `None` deref (~60 s)

Captured live on `omp/18.3.1` (`omp -p --mode json --tools read,bash,debug`) with `debugpy 1.8.22` importable by `python`. The fixture is a stand-in for `bin/crash.py` with the same shape (helper dereferences a `None` returned by a lookup); the lab's line numbers differ.

```
$ python bin/crash.py; echo exit=$?

    return profile["name"].title()
```

What to notice:

- `launch` stops **on entry** (`Stop reason: entry`) because the built-in debugpy adapter sets `stopOnEntry: true`; the breakpoint is only reached after `continue`.
- Frame ids (`#3`, `#4`) and scope refs (`ref=7`) are what you pass as `frame_id` / `variable_ref`; `scopes`/`evaluate` default to the current stopped frame when omitted.
- `evaluate` in the default `repl` context printed an empty `Result:` for `None`; `context: "watch"` printed `None / NoneType`. `variables` is the reliable way to see a value.
- Zero `edit` cards. The fix comes *after* `terminate`, with evidence in hand.

Nine tool calls, ~25 s wall, and the whole thing reads as a story you can verify.
