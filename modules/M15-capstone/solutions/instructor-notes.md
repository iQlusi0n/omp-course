### Design choices worth defending in class

| Choice | Why | Alternative learners may pick (acceptable?) |
|---|---|---|
| `tools/migrate.py` checks `schema_version` first, then `PRAGMA table_info(users)` before `ALTER TABLE` | idempotent even on a half-migrated DB; second run prints the required `already at version 2` | `try: ALTER … except OperationalError` — fine if the version bump is still guarded |
| `data/lab.sqlite` is the **migrated** v1 DB (ALTER-added column); `generated/` regenerated by `python3 tools/seed_db.py --db /tmp/v2-scratch.sqlite` | spec says "commit the migrated `data/lab.sqlite`" and "regenerate `generated/` **through the tool**"; the `--db` trick regenerates `generated/` without replacing the DB | running the full seed (fresh v2 DB, same rows). Acceptable if stated; the diff in `CREATE TABLE` vs `ALTER` is visible in `sqlite3 data/lab.sqlite .schema` |
| `db.list_orders(month, limit, offset, status, user_id)` with a `where` list | one query path for `/orders`, the new route and the CLI; filters AND together by construction | a separate `list_user_orders()` — fine |
| The seeded `LIMIT ? OFFSET ?` / `[offset, limit]` bug (#2) is left **as is** | v2 is unpaginated (`limit=None`); fixing it is scope creep | a learner who fixes it must say so; `LAB_ISSUE=all` then shows 14 failures |
| Route regex `^/users/(\d+)/orders$` checked **after** `^/users/(\d+)$` | mirrors existing style; order does not matter because both are anchored | a single regex with an optional group — fine |
| Status validated **before** the user lookup | a bad status is a client error regardless of user; also cheaper | 404-first — acceptable, spec is silent |
| `POST /signup`: `company` optional; non-string → 400; blank → `null` | the web form always sends the key only when non-empty, but curl users will send `""` | storing `""` — weak; spec says `null` when unset |
| Issue #8 validation **not** implemented | spec: "recommended", not required; the gated tests for #8 still fail on the solution | implementing it is acceptable if `LAB_ISSUE=8` then passes and notes say so |
| `VERSION`/`SERVICE_NAME` in `api/server.py` untouched (`/health` still `1.0`) | V2-SPEC does not ask for it; `docs/spec.md` heading is v2 (the *document* version) | bumping to `2.0` with a spec update — fine |
| CLI summary line becomes `N orders for 2026-03 (completed), total $…` only when `--status` is given | table and summary unchanged without the flag (`test_orders_table_unchanged_without_status`) | any wording, as long as the no-flag output is byte-identical |
| Docs as a 4th commit | keeps the three code slices atomic; spec says "at least three" | folding docs into each slice — fine |

## Common failure modes (seen while building, or predictable from the modules)

1. **`generated/schema_info.py` still says 1.** The learner migrated the DB but never re-ran the seeder; or ran it with `--no-generated`. Fix: `python3 tools/seed_db.py --db /tmp/scratch.sqlite`. If they *hand-edited* it, the TTSR rule (E1) or `edit.blockAutoGenerated` should have refused — check the transcript for the refusal card; its absence means the rule was never loaded (wrong directory, or `omp` started outside the lab root).
2. **Fresh seed replaced the migrated DB** (`git diff --stat` shows `data/lab.sqlite` changed twice, or the schema shows `company` inside `CREATE TABLE`). Not wrong per se; the rubric asks for a note.
3. **`/review` gate fails on seeded bugs.** The headless reviewer reads whole files and lists issues #1, #2, #6, #7, #8 as `P1`, votes `fail`. The learner must scope the review (one sentence), not fix the issues. A learner who "fixed" them to pass the gate gets the scope-creep deduction.
4. **Browser signup lands in the committed DB.** `git status` shows `data/lab.sqlite` modified after Phase 3; the extra user then breaks `test_seed_shape`-style expectations (users ≥ 10 still holds, but `users: 12` in `test_health` fails). Run the server on a scratch `DATABASE_URL`, or `git checkout data/lab.sqlite`.
5. **Port 8080 already taken** (another learner's server, or a leftover service): `python3 -m api --port 18080` and open that URL in the browser cell; the ISSUES.md curl repros assume 8080.
6. **`debug` → `No debugger adapter available`.** `debugpy` must be importable by the interpreter that `python` (not `python3`) resolves to, or add `.omp/dap.json` with `command: python3` (M8 §8.4 has the exact JSON).
7. **`learn` not offered.** Both `autolearn.enabled` and `memory.backend` default off; both must be set and omp restarted. Under `memory.backend: local`, `learn` is `write`-tier (prompts under `always-ask`/`write`).
8. **Scouts refused with a schema error.** `outputSchema` must be a JSON Schema object; `schema` (legacy) is not a field. Under plan mode, `isolated` is not accepted.
9. **`omp commit` produced one giant commit.** They never staged per slice. Recovery: `git reset --soft module-15-start`, then stage and `omp commit` four times.
10. **`/export` fails with `Cannot export in-memory session`.** They ran the capstone with `--no-session`. `/share` still works (snapshot from live entries); ask for the share link plus `/dump` as substitute for E10's HTML, with a deduction.
11. **Plan annotations exist but edits started earlier.** Usually the learner ran a "quick fix" prompt before `Alt+Shift+P`. E2 scores 1; the export makes the order unambiguous.
12. **`omp ttsr list` empty.** The rule file lacks a trigger/description, or the command was run outside the lab root (scope globs are root-relative).
