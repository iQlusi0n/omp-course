# Demo 15.2 — `ci/review.sh` on the finished v2 diff (two real runs, omp/18.3.1)

Shown before Phase 3 step 3. The script is the Module 13 solution (`modules/M13-headless-scripted-embedded/solutions/ci-review.sh` + `ci.yml`) copied into the lab's `ci/`. It runs `omp -p --mode json --no-session --no-extensions --no-skills --config ci/ci.yml --tools read,grep,glob --max-time 4m "/review …"` and parses a JSON verdict from the last assistant `message_end`; it exits `1` on any `P0` **or** `verdict: fail`.

Setup: a scratch clone of the reference solution with its four commits collapsed into one unstaged diff, so `/review` sees the whole v2 change as the working diff.

```
$ git clone -q -b capstone-solution omp-course-lab /tmp/lab-review && cd /tmp/lab-review
$ git reset -q --mixed module-15-start && git status --short | wc -l
16
$ cp <course>/modules/M13-headless-scripted-embedded/solutions/ci-review.sh ci/review.sh
$ cp <course>/modules/M13-headless-scripted-embedded/solutions/ci.yml      ci/ci.yml
```

## Run 1 — script as shipped by Module 13: **fails**, and the findings are not v2's

```
$ ./ci/review.sh --max-time 4m; echo "exit=$?"
P1  api/db.py:99  LIMIT/OFFSET parameters are swapped ([offset, limit]), so each page returns the wrong number of rows
P1  api/server.py:156  offset = page * PAGE_SIZE skips the first page; it should be (page - 1) * PAGE_SIZE
P1  api/db.py:65  count_orders filters status != 'canceled', but the stored status is 'cancelled', so order_count includes cancelled orders
P1  cli/format.py:6  money() divides cents by 10 instead of 100, so amounts show 10x too large
P1  api/server.py:176  _signup returns 500 for a missing name/email (KeyError) or a duplicate email (IntegrityError), and accepts emails without '@'; expected 400/409
P1  api/db.py:31  db_path passes a sqlite:/// DATABASE_URL straight to sqlite3.connect without removing the prefix, so the documented .env.example form fails
P1  api/db.py:43  connect() turns every OperationalError into a made-up 'database is locked' message that hides the real cause and path
P2  api/server.py:76  500 responses send repr(e) and traceback lines to clients, exposing internal details
P2  api/db.py:100  'with sqlite3.connect()' commits but never closes the connection, so every call leaks a connection
review: 9 finding(s), 0 P0, verdict=fail
exit=1
```

Read it as a senior engineer would: every `P1` is a **seeded issue** from `docs/ISSUES.md` (#2, #2, #7, #1, #8, #6, #6) that `docs/V2-SPEC.md` says is out of scope — the reviewer read whole files, not just the hunks. Nothing here is a v2 regression, but the gate still fails because the model voted `fail`. `cli/format.py:6` is not even in the diff.

## Run 2 — one scope sentence added to the `/review` prompt: **passes**

```
$ sed -i 's|PROMPT="/review Respond with ONLY|PROMPT="/review Scope: only lines added or changed by this diff count. Pre-existing bugs documented in docs/ISSUES.md (issues #1-#8) are known and out of scope: do not list them and do not let them affect the verdict. Respond with ONLY|' ci/review.sh
$ ./ci/review.sh --max-time 4m; echo "exit=$?"
review: 0 finding(s), 0 P0, verdict=pass
exit=0
```

What to notice:

- `/review` under `-p` accepts trailing text as review focus (M13 BUILD-NOTES); the scope sentence is the same thing you would say to a human reviewer of a PR in a repo with a known-bugs list.
- The gate is only as good as its prompt: run 1 would have blocked a correct change for the wrong reasons. Evidence **E9** is the passing run *plus* one sentence in `notes/capstone.md` on why the first run failed.
- Wall time: 29 s (run 1) and 83 s (run 2) with the default model; `--max-time 4m` is the safety cap (`Deadline exceeded`, exit `1`).
