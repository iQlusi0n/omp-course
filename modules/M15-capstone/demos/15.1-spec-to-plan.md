# Demo 15.1 — From `docs/V2-SPEC.md` to four work items (real run, omp/18.3.1)

Shown before Phase 1. One headless, read-only prompt from the lab root at `module-15-start`. Nothing in `.omp/` yet — which is exactly the point of the last line.

```
$ cd omp-course-lab
$ omp -p --no-session --no-extensions --no-skills --tools read --max-time 2m \
  "Read docs/V2-SPEC.md. List the four v2 work items as a numbered list; for each give one line: files likely touched, and the tests to add. No more than 12 lines total." 2>/dev/null
1. **Migration (`users.company`, schema v2).** Files: new `tools/migrate.py`, `tools/seed_db.py`, `generated/schema_info.py` (regenerated by a tool, not edited by hand), `data/lab.sqlite`, and probably `api/db.py`. Tests (`tests/test_db.py`): migrating a v1 DB adds `company` and sets version 2; a second run prints `already at version 2` and changes nothing; a fresh seed is already v2.
2. **`GET /users/<id>/orders`, plus `company` on `/users/<id>`.** Files: `api/server.py`, `api/db.py`. Tests (`tests/test_api.py`): newest-first shape and `count`; `?status=` filter; unknown status returns 400 listing the valid statuses; missing user returns 404; `company` is null when unset.
3. **`cli orders --status`.** Files: `cli/__main__.py`, `cli/commands.py`, probably `api/db.py`. Tests (`tests/test_cli.py`): filtering by status alone; `--month` and `--status` together (AND); an invalid status exits with code 2.
4. **Web `company` field.** Files: `web/index.html`, `web/app.js`, `api/server.py` (`/signup`), `api/db.py`. Tests (`tests/test_api.py`): signup with `company` stores it and returns it in the 201 body; signup without it still works.

Also for acceptance: update `docs/spec.md`, regenerate `docs/spec.pdf`, add the new command and flag to `README.md`, and make at least three commits.

`tools/` has no script that obviously generates `generated/schema_info.py`, so I still need to find the "tool" the spec means.
```

What to notice:

- The four items and their tests are already the skeleton of the Phase 1 plan (slices A–D) — the spec is good enough that a plan should *not* invent scope.
- The model correctly flags that `generated/` is regenerated "by a tool, not edited by hand", but with only `read` and no `.omp/AGENTS.md` it does not know **which** tool (`tools/seed_db.py` writes `generated/schema_info.py`). Phase 0 puts that fact in `AGENTS.md` so every later session starts knowing it; `read tools/seed_db.py` would also have answered it.
- `2>/dev/null` hides the `Working...` progress line (M13 §13.1); `--no-session` keeps this throwaway run out of `/resume`.

Source: `omp --help` (`-p`, `--no-session`, `--no-extensions`, `--no-skills`, `--tools`, `--max-time`), omp://cli-reference.md
