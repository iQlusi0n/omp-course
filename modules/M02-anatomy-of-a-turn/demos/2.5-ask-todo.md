# Demo 2.5 — An `ask` picker and a `todo` plan (~40 s)

Shapes: `omp gallery --plain -w 100 --tool ask -s "in progress"|done` and `--tool todo` (omp 18.3.1); content adapted to lab issue #2.

## 1. The model asks (picker open, composer replaced)

Call arguments (under `Ctrl+O`):

```json
{"questions":[
  {"id":"scope","question":"How far should the fix for #2 go?",
   "options":[
     {"label":"Fix only the bug","description":"Two one-line changes"},
     {"label":"Fix and add a regression test","description":"Adds tests/test_issue2.py"},
     {"label":"Fix and refactor the module","description":"Larger diff; touches cli/__main__.py structure"}],
   "recommended":1},
  {"id":"after","question":"After the change:","multi":true,
   "options":[{"label":"Run the full suite"},{"label":"Run only the new test"},{"label":"Show me the diff"}]}
]}
```

On screen:

```text
╭─── Ask 2 questions ──────────────────────────────────────────────────────────────────────────────╮
├─── [scope] · options:3 ──────────────────────────────────────────────────────────────────────────┤
│  How far should the fix for #2 go?                                                               │
│  ○ Fix only the bug                                                                              │
│    ↳ Two one-line changes                                                                        │
│  ○ Fix and add a regression test (Recommended)                                                   │
│    ↳ Adds tests/test_issue2.py                                                                   │
│  ○ Fix and refactor the module                                                                   │
│    ↳ Larger diff; touches cli/__main__.py structure                                              │
├─── [after] · multi · options:3 ──────────────────────────────────────────────────────────────────┤
│  After the change:                                                                               │
│  ☐ Run the full suite                                                                            │
│  ☐ Run only the new test                                                                         │
│  ☐ Show me the diff                                                                              │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

The picker adds its own rows: `Other (type your own)` on every question, `Done selecting` on the multi group once something is checked; ←/→ move between questions keeping earlier answers. The status line notifies `Waiting for input` (`ask.notify: on`). With `ask.timeout: 0` (default) it waits indefinitely; in plan mode it always waits.

## 2. Answered

```text
╭─── ✔ Ask 2 questions ────────────────────────────────────────────────────────────────────────────╮
├─── [scope] ──────────────────────────────────────────────────────────────────────────────────────┤
│  How far should the fix for #2 go?                                                               │
│  ○ Fix only the bug                                                                              │
│  ◉ Fix and add a regression test                                                                 │
│  ○ Fix and refactor the module                                                                   │
├─── [after] ──────────────────────────────────────────────────────────────────────────────────────┤
│  After the change:                                                                               │
│  ☑ Run the full suite                                                                            │
│  ☐ Run only the new test                                                                         │
│  ☑ Show me the diff                                                                              │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

Model-facing text:

```text
User answers:
scope: Fix and add a regression test
after: Run the full suite, Show me the diff
```

With `ask.timeout: 20` and nobody at the keyboard, the first question resolves to the recommended option and the text carries ` (auto-selected after timeout)`. Choosing `Other (type your own)` opens an editor; its text becomes the answer (an optional note is reported as `User added note: …`). `Esc` in the picker cancels the tool **and** the turn.

## 3. The plan

`todo` call 1 — `init`:

```json
{"op":"init","list":[
  {"phase":"Locate","items":["Find both sides of the #2 bug","Confirm with a failing test"]},
  {"phase":"Fix","items":["Patch api and cli","Run the suite"]}]}
```

```text
╭─── ☑ Todo 4 tasks ───────────────────────────────────────────────────────────────────────────────╮
│ I. Locate  0/2                                                                                   │
│   ├─ ☐ Find both sides of the #2 bug                                                             │ ◀ in_progress (highlighted in the TUI; `[/]` in /todo markdown)
│   └─ ☐ Confirm with a failing test                                                               │
│ II. Fix  0/2                                                                                     │
│   ├─ ☐ Patch api and cli                                                                         │
│   └─ ☐ Run the suite                                                                             │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

The first pending task is auto-promoted to `in_progress` (single-active-task rule). The same tree appears in the sticky HUD above the composer; `/todo expand` shows everything, `/todo collapse` returns to the bounded preview.

`todo` call 2 — `done` on one task, then `start` on the next:

```json
{"op":"done","task":"Find both sides of the #2 bug"}
{"op":"start","task":"Patch api and cli"}
```

```text
╭─── ☑ Todo 4 tasks ───────────────────────────────────────────────────────────────────────────────╮
│ I. Locate  1/2                                                                                   │
│   ├─ ☑ Find both sides of the #2 bug                                                             │
│   └─ ☐ Confirm with a failing test                                                               │
│ II. Fix  0/2                                                                                     │
│   ├─ ☐ Patch api and cli                                                                         │ ◀ in_progress
│   └─ ☐ Run the suite                                                                             │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

A `block` with a reason:

```json
{"op":"block","task":"Run the suite","reason":"waiting for user to confirm test scope"}
```

Blocked tasks are skipped by auto-promotion, so a list can have no active task while everything open is blocked. Closed rows fade from the HUD after `tasks.todoClearDelay` (60 s) — display only; the transcript card is permanent.

A bad op (`{"op":"done","task":"task-3"}`) returns `Errors: Task "task-3" not found …` with a hint that tasks are addressed by content, the mutation is discarded, and the HUD shows `Todo update failed…` until the next good call.

Source: omp://tools/ask.md, omp://tools/todo.md, omp://settings.md, `omp gallery --plain --tool ask|todo`.
