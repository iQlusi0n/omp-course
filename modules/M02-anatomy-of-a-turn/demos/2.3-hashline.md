# Demo 2.3 — A tag, an edit, a stale tag, a recovery (~45 s)

Model-facing text is in the exact format `omp read` prints (omp 18.3.1) and the patch grammar from omp://tools/edit.md. Card shapes from `omp gallery --plain --tool edit -s done|failed`. Tags and line contents are illustrative for the lab file `cli/log.py`.

## 1. What the model reads

```text
[cli/log.py#4E9A]
1:"""Tiny logger used by the CLI."""
2:import sys
3:
4:LEVEL = "INFO"
5:
6:
7:class Logger:
8:    def __init__(self, stream=sys.stderr):
9:        self.stream = stream
10:
11:    def debug(self, msg):
12:        if LEVEL == "DEBUG":
13:            self.stream.write(f"[debug] {msg}\n")
14:
15:
16:logger = Logger()
```

`#4E9A` = four-hex hash of the whole normalized file, recorded in the session snapshot store together with the line range shown (all 16 lines here).

## 2. What the model sends to `edit`

```text
[cli/log.py#4E9A]
PUT 4.=4:
+DEBUG_LEVEL = "DEBUG"
PUT 12.=12:
+        if LEVEL == DEBUG_LEVEL:
```

Both line numbers refer to the `#4E9A` snapshot; the second op is *not* shifted by the first.

## 3. What you see

```text
╭─── ✎ Edit: 🟦 cli/log.py ⟦+2/-2⟧ ────────────────────────────────────────────────────────────────╮
│@@ -4,1 +4,1 @@                                                                                   │
│-LEVEL = "INFO"                                                                                   │
│+DEBUG_LEVEL = "DEBUG"                                                                            │
│@@ -12,1 +12,1 @@                                                                                 │
│-········if LEVEL == "DEBUG":                                                                     │
│+········if LEVEL == DEBUG_LEVEL:                                                                 │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

## 4. What the model gets back (receipt)

```text
[cli/log.py#A310]
4:DEBUG_LEVEL = "DEBUG"
…
12:        if LEVEL == DEBUG_LEVEL:
```

A fresh tag (`#A310`). The next edit to this file can use it without another `read`.

## 5. You change the file behind omp's back

In another terminal: open `cli/log.py`, add a comment on line 2, save. The file's hash is now neither `#4E9A` nor `#A310`.

## 6. The model tries to edit with the tag it holds

```text
[cli/log.py#A310]
PUT 1.=1:
+"""Tiny logger used by the CLI (level is DEBUG_LEVEL)."""
```

Two outcomes are possible, both correct:

**(a) Recovered.** The snapshot store can prove that line 1 in the current file is the same line the model saw and that nothing else about the anchor is ambiguous, so the edit lands and the receipt carries a warning:

```text
[cli/log.py#5D77]
1:"""Tiny logger used by the CLI (level is DEBUG_LEVEL)."""

Warnings:
- stale snapshot #A310 recovered against current file content
```

**(b) Refused.** The store cannot prove a unique safe result (say you edited the same region), so the tool returns a mismatch and the model re-reads. In the transcript:

```text
╭─── ✘ Edit: 🟦 cli/log.py ────────────────────────────────────────────────────────────────────────╮
│Snapshot #A310 is stale and cannot be recovered safely: current content near line 1 differs from  │
│the recorded snapshot. Re-read the file and retry with the current tag.                           │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯

╭─── • Read cli/log.py ────────────────────────────────────────────────────────────────────────────╮
│   1 """Tiny logger used by the CLI."""                                                           │
│   2 # touched by hand                                                                            │
│   3 import sys                                                                                   │
│ … 14 more lines ⟦Ctrl+O: Expand⟧                                                                 │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯

╭─── ✎ Edit: 🟦 cli/log.py ⟦+1/-1⟧ ────────────────────────────────────────────────────────────────╮
│@@ -1,1 +1,1 @@                                                                                   │
│-"""Tiny logger used by the CLI."""                                                               │
│+"""Tiny logger used by the CLI (level is DEBUG_LEVEL)."""                                        │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

`✘ Edit` → `• Read` → `✎ Edit` is the signature. The exact wording of the refusal message is illustrative; the categories ("stale snapshot that cannot be recovered safely", "unknown snapshot tag", "outside the recorded seen-line ranges") are the documented ones.

## 7. Why a `:raw` read can't be edited

```text
$ omp read cli/log.py:raw
"""Tiny logger used by the CLI."""
import sys
…
```

No header, no line prefixes → nothing to anchor. Same for `artifact://`, `skill://`, `agent://`, `omp://`.

## 8. A block edit (`PUT N*:`)

Request: "replace the whole `debug` method as one block". The model anchors the `def` line and the tree-sitter node extends to the end of the method:

```text
[cli/log.py#5D77]
PUT 12*:
+    def debug(self, msg):
+        if LEVEL == DEBUG_LEVEL:
+            self.stream.write(f"[debug] {msg}\n")
+            self.stream.flush()
```

Receipt includes a block-resolution line (which lines the block resolved to). Anchoring a closing line, a blank line, or a single-line node is rejected with guidance to use an explicit range instead.

Source: omp://tools/edit.md, omp://tools/read.md, `omp read`, `omp gallery --plain --tool edit`.
