# Demo 2.3 — A tag, an edit, a stale tag, a recovery (~45 s)

Model-facing text is in the exact format `omp read` prints (omp 18.3.1) and the patch grammar from omp://tools/edit.md. Card shapes from `omp gallery --plain --tool edit -s done|failed`. The file is the lab's real `cli/log.py` (17 lines); its tag on `module-2-start` is `#BB9A`, later tags are illustrative.

## 1. What the model reads

```text
[cli/log.py#BB9A]
1:"""Logger for the CLI.
2:
3:``logger`` writes bare messages to stdout at DEBUG level, so it is a drop-in
4:replacement for ``print(msg)`` (Module 8 codemod fixture): swapping
5:``print(x)`` for ``logger.debug(x)`` keeps the CLI tests green.
6:"""
7:
8:import logging
9:import sys
10:
11:logger = logging.getLogger("lab.cli")
12:if not logger.handlers:
13:    _handler = logging.StreamHandler(sys.stdout)
14:    _handler.setFormatter(logging.Formatter("%(message)s"))
15:    logger.addHandler(_handler)
16:logger.setLevel(logging.DEBUG)
17:logger.propagate = False
```

`#BB9A` = four-hex hash of the whole normalized file, recorded in the session snapshot store together with the line range shown (all 17 lines here).

## 2. What the model sends to `edit`

```text
[cli/log.py#BB9A]
PUT 11.=11:
+logger = logging.getLogger("lab.cli.v2")
```

The line number refers to the `#BB9A` snapshot. (With two ops in one call, the second is *not* shifted by the first.)

## 3. What you see

```text
╭─── ✎ Edit: 🟦 cli/log.py ⟦+1/-1⟧ ────────────────────────────────────────────────────────────────╮
│@@ -11,1 +11,1 @@                                                                                 │
│-logger = logging.getLogger("lab.cli")                                                            │
│+logger = logging.getLogger("lab.cli.v2")                                                         │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

## 4. What the model gets back (receipt)

```text
[cli/log.py#A310]
11:logger = logging.getLogger("lab.cli.v2")
```

A fresh tag (`#A310`). The next edit to this file can use it without another `read`.

## 5. You change the file behind omp's back

In another terminal: open `cli/log.py`, add a comment on line 8 (`import logging  # stdlib`), save. The file's hash is now neither `#BB9A` nor `#A310`.

## 6. The model tries to edit with the tag it holds

```text
[cli/log.py#A310]
PUT 1.=1:
+"""Logger for the CLI (logger name: lab.cli.v2).
```

Two outcomes are possible, both correct:

**(a) Recovered.** The snapshot store can prove that line 1 in the current file is the same line the model saw and that nothing else about the anchor is ambiguous, so the edit lands and the receipt carries a warning:

```text
[cli/log.py#5D77]
1:"""Logger for the CLI (logger name: lab.cli.v2).

Warnings:
- stale snapshot #A310 recovered against current file content
```

**(b) Refused.** The store cannot prove a unique safe result (say you edited the same region), so the tool returns a mismatch and the model re-reads. In the transcript:

```text
╭─── ✘ Edit: 🟦 cli/log.py ────────────────────────────────────────────────────────────────────────╮
│Snapshot #A310 is stale and cannot be recovered safely: current content near line 1 differs from  │
│the recorded snapshot. Re-read the file and retry with the current tag.                           │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯

╭─── • Read cli/log.py ────────────────────────────────────────────────────────────────────────────╮
│   1 """Logger for the CLI.                                                                       │
│   2                                                                                              │
│   3 ``logger`` writes bare messages to stdout at DEBUG level, so it is a drop-in                 │
│ … 14 more lines ⟦Ctrl+O: Expand⟧                                                                 │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯

╭─── ✎ Edit: 🟦 cli/log.py ⟦+1/-1⟧ ────────────────────────────────────────────────────────────────╮
│@@ -1,1 +1,1 @@                                                                                   │
│-"""Logger for the CLI.                                                                           │
│+"""Logger for the CLI (logger name: lab.cli.v2).                                                 │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

`✘ Edit` → `• Read` → `✎ Edit` is the signature. The exact wording of the refusal message is illustrative; the categories ("stale snapshot that cannot be recovered safely", "unknown snapshot tag", "outside the recorded seen-line ranges") are the documented ones.

## 7. Why a `:raw` read can't be edited

```text
$ omp read cli/log.py:raw
"""Logger for the CLI.

…
```

No header, no line prefixes → nothing to anchor. Same for `artifact://`, `skill://`, `agent://`, `omp://`.

## 8. A block edit (`PUT N*:`)

`cli/log.py` has no function to replace, so use `api/db.py` (tag `#9F28` on `module-2-start`). Request: "replace the whole `count_orders_in_month` function as one block". The model anchors the `def` line (90) and the tree-sitter node extends to the end of the function:

```text
[api/db.py#9F28]
PUT 90*:
+def count_orders_in_month(month: str | None) -> int:
+    """Rows in ``orders`` for ``month`` (``YYYY-MM``); all rows when month is None."""
+    sql = "SELECT COUNT(*) AS n FROM orders"
+    args: list = []
+    if month:
+        sql += " WHERE substr(created_at, 1, 7) = ?"
+        args.append(month)
+    with connect() as conn:
+        return int(conn.execute(sql, args).fetchone()["n"])
```

Receipt includes a block-resolution line (which lines the block resolved to). Anchoring a closing line, a blank line, or a single-line node is rejected with guidance to use an explicit range instead.

Source: omp://tools/edit.md, omp://tools/read.md, `omp read`, `omp gallery --plain --tool edit`.
