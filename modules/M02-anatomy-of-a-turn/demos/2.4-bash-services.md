# Demo 2.4 — `!`, auto-background, and a named service through `proc://` (~60 s)

Shapes: `omp gallery --plain -w 100 --tool bash|bash_service|read_proc_list|read_proc_service|read_proc_job|write_proc_stop|write_proc_cancel` (omp 18.3.1). Content adapted to `omp-course-lab` (`python3 -m api` serves on 127.0.0.1:8080).

## 1. Your own shell — no model turn

Type `!git status --short` in the composer:

```text
 ! git status --short
   M api/db.py
   M api/server.py
```

That is the user bang-command block (last 20 logical lines collapsed). No tool card, no tokens. `!cd api && pwd` followed by `!pwd` both print `…/omp-course-lab/api` — the shell session persists.

## 2. A command that outlives 60 s

Prompt: `Run: python3 -c "import time; time.sleep(70); print('done')"`

```text
╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ $ python3 -c "import time; time.sleep(70); print('done')"                                        │
├─── Output ───────────────────────────────────────────────────────────────────────────────────────┤
│ Backgrounded as job bash-3; result will be delivered automatically.                              │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯

 The sleep is running in the background (job bash-3). Meanwhile I'll check the schema…

 🔍 Grep: CREATE TABLE 3 matches · 1 files · in tools
 ├─ # tools/
 │  ## seed_db.py
 │  *39│CREATE TABLE users (
 └─ … 2 more matches
```

…and a little later, delivered as its own update:

```text
 ⓘ Proc bash-3
 ✔ ⟦bash⟧ bash-3 python3 -c "import time; time.sleep(70); print('done')" 70.1s
   ▏ done
```

`read proc://` while it runs:

```text
 ⓘ Proc jobs & services 1 jobs · 0 services
 └─ ⏳ ⟦bash⟧ bash-3 python3 -c "import time; time.sleep(70); print('done')" 31.0s
```

`write proc://bash-3/kill` if you change your mind:

```text
 ⏹ Proc kill bash-3
 └─ ⏹ ⟦bash⟧ bash-3 python3 -c "import time; time.sleep(70); print('done')" 31.0s ⟦cancelled⟧
```

## 3. The lab API as a named service

Prompt: `Run the API as a service named api, ready on port 8080.`

The model's call (visible under `Ctrl+O`):

```json
{"command":"python3 -m api","name":"api","ready":{"port":8080}}
```

Card while waiting for readiness, then when ready:

```text
╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ $ python3 -m api                                                                                 │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯

╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ $ python3 -m api                                                                                 │
├─── Output ───────────────────────────────────────────────────────────────────────────────────────┤
│ api: ready pid=51234 ready                                                                       │
│ omp-course-lab API v1 1.0 listening on http://127.0.0.1:8080 (db: …/data/lab.sqlite)            │
│ ⟦Service: api | State: ready | Ready: yes | PID: 51234⟧                                          │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

If the port is taken, the same card fails fast:

```text
╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ $ python3 -m api                                                                                 │
├─── Output ───────────────────────────────────────────────────────────────────────────────────────┤
│ api: failed — process exited before readiness                                                    │
│ ⟦Service: api | State: failed | Ready: no⟧                                                       │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```


## 7. PTY (`pty: true`) — interactive `python3`

The card is replaced by a `Console` overlay while it runs; your keys go to the process; `Esc` kills it. When it ends, a normal bash card records the captured output:

```text
╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ $ python3                                                                                        │
├─── Output ───────────────────────────────────────────────────────────────────────────────────────┤
│ Python 3.12.3 (main) [GCC 13.2.0] on linux                                                       │
│ >>> 1+1                                                                                          │
│ 2                                                                                                │
│ >>>                                                                                              │
│ ⟦Wall: 12.4s | Timeout: 300s⟧                                                                    │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

Where a PTY isn't available (`--no-pty`, `-p`, RPC), the same call runs plainly and the output ends with `pty requested but unavailable in this environment; ran without a terminal`.
