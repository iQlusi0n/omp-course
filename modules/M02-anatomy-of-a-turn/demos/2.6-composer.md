# Demo 2.6 — Composer chords in one sitting (~50 s)

Composer shape: `omp gallery --plain --surface composer` (default `band`); chords from omp://keybindings.md (omp 18.3.1). Autocomplete/queue indicator rows are described, not reproduced pixel-exact.

## 1. `@` mention

```text
╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ @docs/ISS▌                                                                                       │
╰─ Ask anything, edit files, run tools                                                            ─╯
   docs/ISSUES.md                              ◀ fuzzy path autocomplete (Enter to accept)
   docs/spec.md
```

After Enter and typing the rest:

```text
│ @docs/ISSUES.md summarize issue #2 in two lines                                                  │
```

The file content is inlined into the message (a `fileMention` entry in the session) — no `read` card appears in the transcript. Same thing from the shell: `omp @docs/ISSUES.md "summarize issue #2"`.

## 2. Image paste

`Ctrl+V` with a PNG on the clipboard:

```text
│ [Image #1, 1280x720] what is wrong with this form?                                               │
```

Text on the clipboard instead pastes text; a very long paste collapses to `[Paste #2, +30 lines]` (use `Ctrl+Shift+V` to paste text raw). On Windows Terminal use `Alt+V`.

## 3. Queue a follow-up while a turn runs (`Ctrl+Q` / `Ctrl+Enter`)

```text
 ⠹ 12s > ⬢ Sonnet 4.5 · ◒ high ▶─────────╎───┃───◀ ⑂ main · ◫ 14.1%/200K ⟲       ◀ turn running
╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ Now do the same for cli/▌                                                                        │
╰─ Ask anything, edit files, run tools                                                            ─╯
```

Press `Ctrl+Q`: the editor clears and a queued indicator shows one pending message. When the running turn ends, the queued message is submitted automatically — the transcript shows two user prompts back-to-back with no idle gap:

```text
╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ > Summarize every function in api/                                                               │
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
 … (cards + answer) …
╭──────────────────────────────────────────────────────────────────────────────────────────────────╮
│ > Now do the same for cli/                                                                       │  ◀ delivered from the queue
╰──────────────────────────────────────────────────────────────────────────────────────────────────╯
```

`followUpMode: one-at-a-time` (default) delivers one queued message per turn; `all` sends every queued message together.

## 4. Dequeue (`Alt+Up` / `Shift+Up`)

With a message queued, `Alt+Up` pulls it back:

```text
│ Now do the same for cli/                                                                         │  ◀ back in the editor, unsent
```

## 5. Clear and recall (`Ctrl+C`, then `Up`)

```text
│ explain the orders endpoint and its tests in detail▌                                             │
```

`Ctrl+C` → editor empties. `Up` →

```text
│ explain the orders endpoint and its tests in detail                                              │  ◀ recalled draft; still unsent
```

Recall is on by default (`composer.recallClearedDrafts: true`), keeps up to 100 cleared drafts in memory for this editor, and is not part of `Ctrl+R` history. A second `Ctrl+C` on an empty editor exits omp.

## 6. History search (`Ctrl+R`) and external editor (`Ctrl+G`)

`Ctrl+R` opens a search over persistent prompt history; typing `orders` narrows to earlier prompts containing it; Enter loads one into the editor. `Ctrl+G` opens the current draft in `$VISUAL`/`$EDITOR`; save-and-quit returns the text to the composer.

## 7. Retry and redraw

A provider error card (`✘ … 529 overloaded`) → `Alt+R` retries the last failed assistant turn. Garbled screen after a terminal resize → `Alt+L` resets the display.

## 8. Vim mode (`tui.vimMode: true`)

Insert mode (default on entry):

```text
│ fix the users endpoint▌                                                                          │
```

`Esc` → Normal mode: the prompt border changes colour and the cursor becomes a block (`tui.vimModeDisplay: text` also prints the mode name). `b` moves back to `endpoint`, `b` again to `users`, `ciw` deletes the word and enters Insert, type `orders`, `Esc`:

```text
│ fix the orders endpoint                                                                          │  ◀ Normal mode
```

`Enter` submits from Normal mode (`Enter`, `Tab`, and all `Ctrl` chords keep their app meaning in every Vim mode). Note `Up`/`Down` here are `k`/`j`; prompt history is only on `Up`/`Down` in Insert mode. To interrupt a running turn from Insert mode press `Esc` twice (first one just switches modes).
