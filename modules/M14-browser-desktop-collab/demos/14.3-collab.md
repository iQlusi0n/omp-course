# Demo 14.3 — Host, join, list (~60 s)

Two terminals. The `/collab` output block below is the example printed in `omp://collab.md` (room id/key are the doc's sample). The `omp collab` CLI lines marked *(observed)* were run on the build machine (no host running, so the empty case); the populated row is the field list documented for `omp collab list`.

## Terminal A — host (lab root)

```
› /collab

Collab session started!
 • Join from another terminal: omp join "mgAYTZwEnpRQtca0CTgn-Q.gdJUbTovD94ofDaa8YvhY0-ty16w4fn8PgB6PLnoA30"
 • or any web browser: my.omp.sh/#mgAYTZwEnpRQtca0CTgn-Q.gdJUbTovD94ofDaa8YvhY0-ty16w4fn8PgB6PLnoA30
 [QR: terminal link]        [QR: browser link]
```

The browser line is an OSC 8 click-to-join hyperlink; the secret after the `.` is 48 bytes (32-byte AES-256-GCM key + 16-byte write token) → this is a **full-control** link. `/collab view` would print a 32-byte (view-only) secret.

## Terminal B — guest (any directory, any machine)

```
$ omp join "mgAYTZwEnpRQtca0CTgn-Q.gdJUbTovD94ofDaa8YvhY0-ty16w4fn8PgB6PLnoA30"
```

B now renders A's session natively: same cards, `Ctrl+O` expansion works, footer shows A's cwd / model / context % / cost. A's transcript shows a join notice with B's `collab.displayName` (OS username by default). If the link were view-only, the notice says so and B appears read-only in the participants list.

```
B › Run the lab test suite and summarize.        ← rendered with B's name badge on both sides
A ┌ bash  python3 -m unittest discover -s tests   ← executes on A's machine only
```

## Terminal C — registry (host machine, any shell)

```
$ omp collab list
No active Collab hosts.                                   (observed — before /collab)

$ omp collab list --json                                  (observed — before /collab)
{
  "version": 1,
  "hosts": []
}
```

With A hosting and B joined, `omp collab list` prints one row per live host with: `instanceId`, `generation`, PID, session id/name, cwd, model, start time, **participant count (2)**, relay-open flag, `inputRequired`, `busy` (`working` while step "Run the lab test suite" executes, `idle` after), and `access` (`control`). Field names in `--json` follow the same list; the exact key spelling is whatever your `omp collab list --json` prints — the course does not pin it.

```
$ omp collab link <instanceId> --json
{"version": 1, "instanceId": "…", "generation": 1, "access": "control", "url": "https://my.omp.sh/#…"}

$ omp collab link <instanceId> --view
https://my.omp.sh/#<roomId>.<32-byte-key>

$ omp collab link 99999                                   (observed)
error: no active Collab host matches 99999                (exit 1)
```

## Guest steers a host subagent (Guided task)

```
A › Use a task subagent to audit api/ for unhandled exceptions; report a list.
A ┌ task  agent=task  "audit api/ …"   (running)

B  Alt+A                                  → Agent Hub lists A's subagent with live progress
B  Enter on the row                       → full-screen transcript viewer (guests have no local focusable session)
B  input line: also audit cli/   ⏎        → steering message; appears in the subagent transcript on A and B
```

`x` in the Hub kills the agent — guests can do that too; don't.

## Tear down

```
B › /leave                 → B's previous session is restored
A › /collab status         → 1 participant, access control
A › /collab stop
$ omp collab list          → No active Collab hosts.
```
