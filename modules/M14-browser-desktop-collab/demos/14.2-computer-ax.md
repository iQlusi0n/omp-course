# Demo 14.2 — AX-first click on the Tk fixture (~60 s)

**Honesty note.** The build machine has no desktop, so this transcript could not be captured live. Every command, return shape, error code, and approval behaviour below is taken from `omp://tools/computer.md`, `omp://computer-use.md`, and `omp://approval-mode.md`; the *values* (window id, pid, bounds, ref numbers) are placeholders. Your first live run replaces them.

Setup: `python3 bin/gui-demo.py` running (window **Lab GUI Demo**, button **Click me**, label **Ready**); lab `.omp/config.yml` has `tools: { approvalMode: write }`.

## 1. Enable for this session, check capabilities

```
› /computer status
  (prints the current session state — disabled)
› /computer on
  (enabled for this session only; settings files untouched)
```

```
┌ eval js
│ display(await computer.capabilities());
│
│ { backend: "<platform backend>", capture: true, input: true, ax: true,
│   capturePermission: "granted", inputPermission: "granted", axPermission: "granted",
│   deliveryModes: ["background", "foreground"], displayServer: "…", displayCount: 1 }
└   (read tier — no prompt)
```

On Wayland release builds expect `capture: false`; on macOS without Screen Recording/Accessibility expect `PermissionDenied` on the first capture/AX call.

## 3. Walk the AX tree, find the button, press it (exec tier → prompt)

```
┌ eval js
│ console.log(await win.ax({ maxDepth: 6 }));
│ const btns = await win.find({ role: "button" });
│ if (btns.length !== 1) throw new Error(`expected one button, got ${btns.length}`);
│ await btns[0].press();
│ console.log((await win.ax()).includes("Clicked!") ? "label changed" : "label unchanged");
│
│ window "Lab GUI Demo" [ref=e1]
│   button "Click me" [ref=e2]
│   label "Ready" [ref=e3]
│
│ [approval prompt — exec tier — details show the resolved JavaScript, e.g. desktop.ref("e2").press()]
│ (approve)
│ label changed
└
```

If `find` returns `[]`, the toolkit is not exposing AX on your platform: fall back to `await win.screenshot()` then `await win.click(x, y)` with pixel coordinates read from **that** screenshot. Clicking with coordinates from an older capture throws `InvalidCoordinateFrame`.

## 4. Same thing as one `computer.run` (Guided task shape)

```
┌ eval js
│ const r = await computer.run(async ({ desktop, wait }, termApp, tkTitle) => {
│   const term = await desktop.window({ app: termApp });
│   await term.screenshot({ silent: true });
│   const tk = await desktop.window({ title: tkTitle });
│   await tk.screenshot({ silent: true });
│   const before = /label "([^"]+)"/.exec(await tk.ax())?.[1];
│   const [btn] = await tk.find({ role: "button" });
│   await btn.press();
│   await wait(async () => (await tk.ax()).includes("Clicked!"), { timeout: 5000, interval: 100 });
│   const after = /label "([^"]+)"/.exec(await tk.ax())?.[1];
│   return { before, after };
│ }, { args: ["<your terminal app>", "Lab GUI Demo"], timeout: 60 });
│ display(r);
│
│ [approval prompt — exec tier because read_only was omitted — details show up to 2 000 chars of resolved JavaScript]
│ (approve)
│ { before: "Ready", after: "Clicked!" }
└
```

The regex assumes the AX tree prints roles as `label "text"`; adjust to what your `ax()` actually prints — that is why the walkthrough has you print the tree first.

## 5. Read-only run is refused at the mutation (Stretch)

```
┌ eval js
│ await computer.run(async ({ desktop }) => {
│   const tk = await desktop.window({ title: "Lab GUI Demo" });
│   const [btn] = await tk.find({ role: "button" });
│   await btn.press();                 // ← rejected
│ }, { read_only: true });
│
│ [read-only mutation error naming press — the prelude blocks facade mutations in read_only runs]

```
