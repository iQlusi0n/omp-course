# Instructor notes — 14.2 Computer, 14.3 Collab, 14.4 Stream/voice

None of these could be executed on the build machine (no desktop, no second participant, no Stencil account). Everything below is grounded in `omp://computer-use.md`, `omp://tools/computer.md`, `omp://collab.md`, `omp://stream.md`, `omp://keybindings.md`, and the CLI `--help`/observed error output. Run each once on your own platform before teaching and replace the placeholder values in `demos/`.

## 14.2-G — screenshot terminal, walk AX, press the Tk button

Reference run (JS):

```js
const r = await computer.run(async ({ desktop, wait }, termApp, tkTitle) => {
  const term = await desktop.window({ app: termApp });
  await term.screenshot({ silent: true });
  const tk = await desktop.window({ title: tkTitle });
  await tk.screenshot({ silent: true });
  const before = await tk.ax({ maxDepth: 6 });
  const [btn] = await tk.find({ role: "button" });
  if (!btn) throw new Error("no AX button — use the pixel fallback");
  await btn.press();
  await wait(async () => (await tk.ax()).includes("Clicked!"), { timeout: 5000, interval: 100 });
  return { before: before.includes("Ready"), after: (await tk.ax()).includes("Clicked!") };
}, { args: ["<terminal app>", "Lab GUI Demo"], timeout: 60 });
```

Grading: exactly one approval prompt (the run is `exec` because `read_only` is omitted — under `tools.approvalMode: write`); return value `{ before: true, after: true }`; a fresh screenshot shows **Clicked!**.

Platform caveats to brief before the session:
- Tk's accessibility exposure differs per platform; if `find({ role: "button" })` is empty, accept the pixel fallback (`screenshot` → `click(x, y)` from *that* screenshot). Grade on the label change, not on the method.
- Wayland release builds: `capabilities().capture === false`; the "screenshot the terminal" part is impossible — accept AX-only evidence (`ax()` of both windows) and say so.
- macOS: the *terminal app* (not omp) needs Screen Recording + Accessibility; a restart of the terminal is required after granting.
- `desktop.window({ app })` throws on multiple matches; have them list with `windows()` and pass the `id`.
- Never let a learner do this outside a VM with `tools.approvalMode: yolo` — under yolo, `press`/`type` never prompt.

14.2-S: the read-only run must fail at `press()` with a read-only mutation error, while the same run can still `return require("os").hostname()` — that is the "trust declaration, not sandbox" point from the docs.

## 14.3-G — host, join, steer from the guest's Hub

Grading evidence: `omp collab list --json` captured while the guest is connected showing `version: 1`, one host, participant count 2; the subagent transcript (`read history://<id>` on the host, or the Hub viewer on the guest) containing the guest's steering text. Field names in the JSON are not pinned by the docs; accept whatever the learner's build prints as long as the count is 2.

Pitfalls:
- The guest joined with a view-only link (`/collab view`): prompting and Hub actions are refused; the join notice says read-only. Host must run `/collab` (upgrade) and hand out the new link.
- Host ran `/new`/`/resume`/`/fork` mid-exercise: room rotated, guest got a goodbye; re-share.
- `omp collab link <pid>` errors with candidates: use the `instanceId`.
- Corporate networks blocking `wss://my.omp.sh`: there is no self-hostable production relay; the local stand-in in the omp source tree is protocol-only and serves no web client. Fall back to two terminals on one machine.
- `busy: null` from an older host means unknown, not idle.

14.3-S: `omp collab link <instanceId> --json` must show `"access": "control"` after the upgrade; `--view` must still return a URL. A `view`-published host refusing `control` is the expected pre-upgrade failure.

## 14.4-S — stream, record, clip

Grading: viewer page (`live.omp.sh/<username>`) shows the pane with `LAB_TOKEN=••••••` and `DATABASE_URL=…` intact; `omp play` replays; `omp clip` prints `live.omp.sh/c/<id>` that plays. Sessions must be started **after** `omp stream` and in the same directory or they never get the `● LIVE` badge.

Redaction rationale (so you can answer "why is the token masked but the URL not"): `.env.example` is not a loaded `.env`, so the "every .env value" rule does not apply; the `NAME=value` rule masks values whose name looks secret — `LAB_TOKEN` matches `*_TOKEN`. `DATABASE_URL=sqlite:///…` has neither a secret-looking name nor a `user:password@` segment.

## 14.4-G — dictation

`omp setup speech --check` must report the STT model installed (fresh machines show `[missing] Speech-to-Text model: parakeet-tdt-0.6b-v3 — not downloaded`). Space push-to-talk works only with `stt.enabled: true` in a **new** session. `stt.submitTrigger` defaults to `never` — Enter is still required. Live voice (`Ctrl+L`/`/live`) is documented only as "Codex-backed realtime voice" with `live.voice: sol`; do not promise more than that.
