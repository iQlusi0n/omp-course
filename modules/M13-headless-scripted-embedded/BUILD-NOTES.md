# Module 13 — build notes

Built against `omp/18.3.1` on the Python-only build machine. A model **was** configured (`omp models` listed the `anthropic` provider), so every print-mode, JSON-mode, RPC, CI-script and host-tool transcript in `demos/` and `solutions/README.md` is real output from `anthropic/claude-haiku-4-5`. Throwaway runs used a scratch repo under `/tmp`; nothing was written to the course tree except this module.

## Verified by execution (not just docs)
- `omp -p` text mode: stdout carries only the answer; `Working...` goes to stderr. Exit `0`.
- Unknown model → message + exit `1`. `--max-time 1` → stderr `Deadline exceeded`, exit `1`, empty stdout.
- `--mode json` event stream: `session`, `agent_start`, `turn_start`, `message_start/update/end` (roles `user`/`assistant`/`toolResult`), `tool_execution_start/end` (`toolCallId`, `toolName`, `args`, `intent`, `result`, `isError`), `turn_end`, `agent_end`. `assistantMessageEvent` types `thinking_*`, `text_*`, `toolcall_*`. The `session` header frame and the `toolResult` role are **not** described in `omp://cli-reference.md`; they are reported as observed.
- `--tools read,grep,glob` removes `write`; `--config` overlay with `tools.approvalMode: always-ask` makes a headless write attempt fail (exit still `0`); `--config … --yolo` lets the write through (runtime flag > overlay, matching settings.md precedence).
- `/review` runs under `-p`; trailing text after `/review` reaches the model and can dictate an output format.
- RPC: `ready` frame fields match rpc.md verbatim; `negotiate_protocol` v2, `get_state`, `prompt` → `prompt_result` → `session_settled`, `abort` → `status:"aborted"`, `steer` mid-turn, `set_host_tools` → `host_tool_call` → `host_tool_result`, malformed line → `command:"parse"` with `id:null` and the loop continues, stdin EOF → exit `0`.
- `ci-review.sh`: exit `1` on P0, `0` on clean diff, `1` on deadline.
- `tools.approvalMode: yolo` + `tools.approval.bash: prompt` under `-p`: `tool_execution_end … isError:true` with text `Tool "bash" requires approval but no interactive UI available.` — basis for the 13.4 stretch and the 13.5 "blocked call" example.
- The inline stdlib RPC snippet in 13.2 was executed as written (printed `hello`, `status=completed`, child exit `0`).

## Deviations from the outline / dropped claims
- **13.2 "TS `RpcClient` and Python `omp-rpc`"** — described only to the extent of rpc.md (constructor kwargs, `get_state`, `prompt_and_wait`, `require_assistant_text`, `get_messages`, `command=[...]`). The install path for `omp-rpc` (PyPI name, pip command) is not in `omp://`; the lesson says "bundled in the omp source tree at `python/omp-rpc`" and ships a stdlib client instead. `setCustomTools()` for the TS helper is mentioned as in rpc.md; no other TS helper methods are claimed.
- **13.3 SDK** — `solutions/sdk-readonly.ts` could not be executed (no Bun). Every identifier and option is copied from `omp://sdk.md`; the `tool_execution_start` event carrying `toolName` is inferred from the identical RPC/JSON event shape observed at runtime (rpc.md says RPC forwards `AgentSession.subscribe` events unchanged). Marked as not runnable here in the lesson.
- **13.4 ACP** — no ACP client on the build machine; nothing executed. The outline cites "README (ACP table)"; there is no README in the `omp://` index, so that source was dropped. Zed-specific configuration keys are not in `omp://` and are therefore **not** stated; the lesson tells learners to consult the editor's docs for registering a custom ACP agent. `omp acp --help` on 18.3.1 prints only a usage line; the `--yolo`/`--auto-approve`/`--approval-mode`/`--config` forms come from `omp://approval-mode.md` (doc wins; noted in the lesson).
- **13.5 "fail-on-P0 from `/review` JSON"** — no documented native JSON output for `/review` exists in `omp://`. Implemented as a prompt-defined JSON verdict appended to `/review`, parsed from the last assistant `message_end` in `--mode json`. Fence stripping added because the model fenced the JSON in every observed run.
- **13.5 `robomp`** — described strictly from `omp://user-facing-packages.md` (webhook triage service resuming an `omp --mode rpc` session per issue; commands `serve|triage|replay|status|cleanup`; dashboard `http://localhost:6543/`). Not installed or run.
- **Exit codes** — `omp://cli-reference.md` does not enumerate exit codes. The lesson reports only the values observed (`0`, `1`) and warns that tool refusals still exit `0`.
- **`pr://`** reads were not exercised (no `gh`/GitHub on the build machine). URI forms are quoted from `omp://tools/read.md`; the `OMP_REVIEW_TARGET=pr://N` path in `ci-review.sh` is therefore untested and flagged as a guided task with `omp read pr://N` as the first checkpoint.
- Lab fixtures (`docs/ISSUES.md`, `cli/__init__.py`, `tests/`, `module-13-start`) were not present while this module was built (lab built in parallel). The wave-2 audit reconciled every fixture reference against the finished lab (see below).
