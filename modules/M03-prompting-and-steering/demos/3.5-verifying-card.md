# Demo 3.5 — A claim without a card, and the truncation footer

Representative transcript (not a recording). `●` tool card, `✗` error-marked card, `⋯` elided.

## The unbacked claim

```text
› Implement issue #3's quoting follow-up but do not run any tests; just report when done.

● read cli/commands.py
● edit cli/commands.py            +3 −2
Done. The CSV writer now quotes fields per RFC 4180 and the tests should pass.
```

"should pass" — no `bash` card above it. Ask for the run:

```text
› You said the tests should pass but nothing was run. Run LAB_ISSUE=3 python3 -m unittest tests.test_issues now and show the output.

✗ bash LAB_ISSUE=3 python3 -m unittest tests.test_issues
    ⋯
    AssertionError: 'a,"b,c",d' != 'a,b,c,d'
    FAILED (failures=1)
    Command exited with code 1
```

The card is error-marked and ends with `Command exited with code <n>`. The prose was wrong; the card is right.

```text
› Summarize the diff per file: path — what changed — why. Then run git diff --stat and paste it.

- cli/commands.py — csv.writer with QUOTE_MINIMAL — RFC 4180 quoting
- cli/__main__.py — added csv to --format choices — enable the flag
● bash git diff --stat
    cli/__main__.py   |  2 +-

› !git diff --stat
    cli/__main__.py   |  2 +-
    cli/commands.py   | 15 ++++++++++++---

```

Same list → the summary is trustworthy. A file in the prose that is missing from `git` (or the reverse) means the model summarized from memory.
