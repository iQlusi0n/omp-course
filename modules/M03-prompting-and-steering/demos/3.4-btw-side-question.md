# Demo 3.4b — `/btw`: a side question that never enters the main transcript

Representative transcript (not a recording).

## Ask inline

```text
main transcript (unchanged below this point) ────────────────────────────────
› Implement issue #3 … (earlier)
● … edit cli/commands.py …
Done: files changed …

› /btw What does the function that renders the orders table in cli/commands.py return, and who calls it?

  ┌ btw ──────────────────────────────────────────────────────────────────────┐
  │ cmd_orders() returns an int exit code (0); it prints the table and the    │
  │ summary line with print(). It is called from main() in cli/__main__.py    │
  │ when args.command == "orders" …                                           │
  │                                                                           │
  │ c copy   f follow-up   b branch   Esc close                               │
  └───────────────────────────────────────────────────────────────────────────┘
```

- The question sees the *current* main context (the issue #3 work above) — that is why it can answer about `cmd_orders` without you pasting anything.
- Nothing is appended to the main transcript; the next main prompt does not receive this Q&A as history.
- `Esc` while it is still answering cancels and keeps the partial text as `Cancelled`; `Esc` again closes the panel.
- `f` (main editor empty and focused) opens a follow-up on this topic; follow-ups keep the topic's earlier answers.
- `b` promotes a *completed single-turn* answer to a chat branch — only if the main session is idle and unchanged since you asked.

## Browse history

```text
› /btw

  ┌ btw history ───────────────┐ ┌ details ──────────────────────────────────┐
  │ ▸ What does the function…  │ │ Q: What does the function that renders …  │
  │   (earlier question)       │ │ A: cmd_orders() returns an int exit code… │
  └────────────────────────────┘ └───────────────────────────────────────────┘
   Up/Down select · Tab switch pane · Enter or f follow-up · Esc close
```

Persistence: per-topic files under the session artifact directory `btw-history/` (memory-only with `--no-session`). Excluded from `/export` and `/share`. One BTW request at a time — a new `/btw` while one is running is refused, not queued. `/move`, `/wt`, and a persistent `!cd` refuse to relocate the session while a BTW is running.
