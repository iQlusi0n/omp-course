# Demo 11.4 — A `tool_call` handler blocks a `bash` call (preview, ≤ 30 s)

Preview only: the extension is **built and loaded in Module 12**. The handler shape below is
copied from `omp://extensions.md` (quick start) and `omp://hooks.md`; the transcript is a
reconstruction of what a blocked call looks like — a tool card ending in an error whose text is the
handler's `reason`. No recording exists on the build machine.

## The handler (from the docs, unchanged in spirit)

```ts
// <cwd>/.omp/hooks/pre/no-force-push.ts   ← must be in pre/ or post/, not hooks/ root
import type { HookAPI } from "@oh-my-pi/pi-coding-agent/extensibility/hooks";

export default function hook(pi: HookAPI): void {
  pi.on("tool_call", async (event, ctx) => {
    if (event.toolName !== "bash") return;
    const cmd = String(event.input.command ?? "");
    if (cmd.includes("push --force") || cmd.includes("push -f")) {
      return { block: true, reason: "force-push is blocked by project policy" };
    }
  });
}
```

Load it explicitly for one run (`--hook` is an alias of `-e/--extension`):

```text
$ omp --hook .omp/hooks/pre/no-force-push.ts
```

or let native discovery pick it up from `.omp/hooks/pre/` on the next start.

## What the model sees (reconstructed)

```text
> The branch is rebased; push it.

  ▸ bash git push --force origin feature/json-flag                        ✗
      Error: force-push is blocked by project policy

  ⋯ The push was refused by a project guardrail. I'll push with --force-with-lease only if you
    confirm; otherwise here is the branch state for you to push manually.
```

Contract recap (`omp://hooks.md` §"Pre-execution: `tool_call`"):

| handler returns | effect |
|---|---|
| `{ block: true, reason }` | execution stops; `reason` becomes the thrown error text; context collected for the call is discarded |
| throws | fails closed — blocked |
| `{ input: {...} }` (no block) | replaces raw execution arguments; last handler wins |
| `{ additionalContext: "…" }` (no block) | delivered after the tool result as trusted instructions |

Contrast with a TTSR rule `condition: "push --force"` + `scope: "tool:bash"`: TTSR would abort the
*stream* while the model was still typing the command and retry with a `<system-interrupt>`;
the hook lets the call be dispatched and returns a tool **error** — the model sees a failed
call, not a rewritten history.
