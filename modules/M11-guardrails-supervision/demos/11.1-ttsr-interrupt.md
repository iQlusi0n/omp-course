# Demo 11.1 — A TTSR rule aborts a `console.log` edit mid-stream (≤ 60 s)

Two parts. **Part A** is real output captured on the build machine during the Wave 2 audit (binary
reported `omp/18.3.5`; no model) with all three `solutions/` rules installed in a copy of the lab
tree. **Part B** is a TUI transcript reconstructed from the verified UI string
`Injecting rule: <name>`; no recording exists on the build machine.

Rule under test: `solutions/no-console-log.md` installed as `.omp/rules/no-console-log.md`.

Notes on what you just saw:
- `evaluated 30` = your 3 rules + 27 embedded builtins; `rules=29` in `scan` because it skips the one `question:` rule (judged rules are not violations).
- The AST rule `no-bare-print` (`solutions/no-bare-print.md`) matched `print(...)` in `cli/commands.py` — the only seeded `print()` sites — and nothing in `cli/__main__.py` (`sys.stderr.write`). The seeded `web/app.js` has no `console.log`, so `no-console-log` reports no match on `scan`.
- Exit codes: every command above exited 0, including the no-trigger `test` — only `-r` isolated mode exits 1 when nothing triggers. Grep the output, not `$?`.
- The judged rule, tested verbosely, reports its question instead of a verdict:

```text
$ omp ttsr test -v -r .omp/rules/no-unverified-tests.md --source text 'All tests pass, the change is verified.'
TTSR test — source=text agent=main snippet=39b

```

## Part B — TUI, reconstructed

```text
> In web/app.js, log the form payload to the console right before the fetch so I can debug submissions.

  ⋯ I'll add a log line before the fetch call.

  ▸ edit web/app.js
      [web/app.js#A3F1]
      PUT >17:
      +  console.lo▌                         ← stream aborted here (regex matched in tool args)

  ⚠ Injecting rule: no-console-log  ↺
      Do not add `console.log(...)` calls to files under `web/`. If diagnostic output is
      genuinely needed, define one helper at the top of the file … use `debug("...")` …

  ⋯ The project rule forbids console.log in web/. I'll add a DEBUG-guarded helper instead.

  ▸ edit web/app.js                                                       ✓
      +const DEBUG = false;
      +function debug(...args) { if (DEBUG) console.warn("[signup]", ...args); }
       …
      +  debug("submitting", payload);

  Added a `debug()` helper guarded by `DEBUG` and called it before the fetch; no `console.log` was added.
```

What happened, in order (from `omp://ttsr-injection-lifecycle.md`):

1. `toolcall_delta` for the `edit` call was reconstructed into a source snapshot; `checkSnapshot` matched `/console\.log/` under scope `tool:edit(web/*.js)`.
2. `interruptMode: always` → `agent.abort()` immediately; `ttsr_triggered` emitted.
3. 50 ms later: `ttsr.contextMode: discard` dropped the partial assistant message; a hidden `custom_message` (`customType: "ttsr-injection"`) carrying `<system-interrupt reason="rule_violation" rule="no-console-log" path="web/app.js">…</system-interrupt>` was appended; `agent.continue()` retried.
4. A `ttsr_injection` entry naming `no-console-log` was persisted → with `repeatMode: once` this rule will not fire again in this session (or after `/resume`).
