# Demo 9.1 — Enabling a backend and inspecting it (~60 s)

> Illustrative transcript (no recording could be captured on the build machine). Shell output lines are real `omp/18.3.1` output. In-session lines use only documented strings (`omp://memory.md`, `omp://mnemosyne-memory-backend.md`); where the exact rendering is not documented the transcript shows `<…>` placeholders. Assistant prose is representative.

```text
$ cd omp-course-lab
$ omp config get memory.backend
off
$ omp config get mnemopi.scoping
per-project

$ cat >> .omp/config.yml <<'EOF'
memory:
  backend: mnemopi
mnemopi:
  scoping: per-project
EOF

$ omp config get memory.backend
mnemopi

$ omp
```

```text
[status line … context_pct 2%]

> /memory stats
  <backend-specific Mnemopi bank statistics for the project bank>

> /memory view
  <current injection payload — empty on a first run>

> which memory tools can you call right now? list them and say which are missing.
  ▸ read xd://
  Available: recall, retain, reflect, memory_edit.
  Missing: learn (needs autolearn.enabled), checkpoint/rewind (need checkpoint.enabled).
```

```text
$ ls ~/.omp/agent/memories/mnemopi/banks/
omp-course-lab-<hash>/          # per-project bank: mnemopi.db (+ -wal/-shm)
```

What to notice:
- The shell `omp config get` only shows `mnemopi` when run *inside* the repo — the project layer is `<cwd>/.omp/config.yml`.
- `/memory stats` rendering statistics proves the backend initialised. If it had failed, the session would continue with Mnemopi inert and the tools would report `Mnemopi backend is not initialised for this session.`
- The tools are *discoverable*; with `tools.xdev` on they are listed by `read xd://` and may render as `write xd://<tool>` cards.
- No `learn` yet: that is `autolearn.enabled`, a separate gate (Lesson 9.3).
