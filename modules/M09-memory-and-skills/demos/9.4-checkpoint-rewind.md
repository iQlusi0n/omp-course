# Demo 9.4 — checkpoint → investigate issue #7 → rewind (~60 s)

> Illustrative transcript (no recording on the build machine). Tool result strings come from `omp://tools/checkpoint.md` and `omp://tools/rewind.md`; the `context_pct` figures are representative, not measured. `checkpoint.enabled: true`, cwd `omp-course-lab/`.

```text
$ omp config get checkpoint.enabled
true
$ omp
```

```text
[status line … context_pct 3%]

> Set a checkpoint with the goal "find the real cause of issue #7 in
  docs/ISSUES.md". Investigate thoroughly — read the code and run the tests.
  When you know the answer, rewind with a report naming the real cause, the
  red herring you ruled out, and the file:line to change. Do not fix anything.

  ▸ checkpoint  goal: "find the real cause of issue #7 in docs/ISSUES.md"
    Checkpoint created.
    Goal: find the real cause of issue #7 in docs/ISSUES.md
    Run your investigation, then call rewind with a concise report.

  ▸ read  docs/ISSUES.md
  ▸ bash  <run the test suite>
  ▸ grep  <the obvious suspect>
  ▸ read  <suspect file>          ← the red herring
  ▸ read  <second file>
  ▸ bash  <targeted repro>
  ▸ read  <the file actually at fault>
  … (a dozen more cards)

[status line … context_pct 31%]

  ▸ rewind  report: "Real cause: <…> in <file>:<line>. Red herring: <the
                     obvious suspect> — its tests pass in isolation and the
                     failing path never reaches it. Change: <file>:<line>."
    Rewind requested.
    Report captured for context replacement.

  Investigation complete; findings are in the rewind report.

[turn ends — rewind applied at turn_end]
[status line … context_pct 6%]

> What was the red herring?

  The report says: <the obvious suspect> — its tests pass in isolation and the
  failing path never reaches it. The real cause is <…> at <file>:<line>.
  (answered from the retained rewind-report; no new investigation, no second rewind)

> /tree      (Alt+A → search "rewind")
  ├─ user: Set a checkpoint with the goal …
  ├─ assistant → checkpoint ✓
  │   ├─ [abandoned branch] read, bash, grep … rewind ✓   ← still in the .jsonl
  │   └─ branch_summary: Real cause: … Red herring: …     ← active branch
  │       └─ custom: rewind-report
  └─ user: What was the red herring?
```

What to notice:
- The `checkpoint` card carries **no id** — `rewind` always targets the one active checkpoint.
- `context_pct` climbs during the investigation and drops only *after the turn ends*, because the rewind is applied at `turn_end`.
- The follow-up question is answered from the `rewind-report` message — the model does not re-read the files, and calling `rewind` again would error with `Checkpoint already completed; …`.
- Nothing on disk was reverted: rewind restores conversation context only.
