# Instructor notes — G1 (learn + managed skill, issue #6)

## Reference flow
1. `omp config get autolearn.enabled` from the repo → `true`. Backend still `mnemopi` (otherwise `learn` is absent; `manage_skill` alone would still work).
2. Solve #6 the Module-3 way. The point of the fixture is that the error text names the wrong place; the lesson must say (a) the misleading text, (b) the real cause, (c) the check to run first.
3. `learn` without `skill` → `Lesson stored.` On Mnemopi this is a `fact` row, `importance 0.8`, `source: coding-agent-learn`.
4. Either:
   - `manage_skill { action: "create", name, description, body }` → `Created managed skill "<name>" (managed-skills/<name>/SKILL.md).` and the skill is usable in the same session; or
   - `learn { memory, skill: { action: "create", name, description, body } }` → `Lesson stored. Created managed skill "<name>".` and the skill is usable after `/new`/restart.
5. `cat ~/.omp/agent/managed-skills/<name>/SKILL.md` → generated frontmatter (`name`, `description`) + body.
6. Fresh session: `read skill://<name>` returns the body.

## Acceptable solutions
- Name must match `[a-z0-9][a-z0-9-]{0,63}` after trim+lowercase. `Lab_Issue6` fails with `Invalid skill name …`; `lab-issue6` passes.
- Body is Markdown *without* frontmatter. If the learner (or model) included `---\nname: …` in the body, the file still gets generated frontmatter on top — accept, but point it out.
- Two `learn` calls (one plain, one with `skill`) will store two lessons on Mnemopi (no dedup across rows). Fine for the exercise; dedup exists only for the `local` backend's `learned.md`.

## Pitfalls
| Seen | Explanation |
|---|---|
| Skill created via `learn` but `skill://<name>` fails immediately | `learn` does not call `refreshSkills`; discovery happens on the next session/refresh. `/new` and retry. |
| `manage_skill create` returns an error with `shadowed: true` | An authored skill (e.g. `.omp/skills/<name>/`) owns the name. Authored always wins; nothing is written. Choose another name. |
| `create` fails: exists | Exclusive create. Use `update`, or `delete` then `create`. |
| Approval prompt appears in `write` mode | Both `manage_skill` (`write`) and `learn` with `skill` (`write`) prompt in `always-ask`; in `write` mode they auto-approve; in `yolo` nothing prompts. If a prompt appears, the learner is in `always-ask` — approve. |
| Learner cannot find the skill under `~/.omp/agent/skills/` | Wrong path. Managed skills live under `~/.omp/agent/managed-skills/`; the outline's path is a deviation logged in `BUILD-NOTES.md`. |
| `--profile` in use | The agent dir moves to the profile; `managed-skills/` is under that profile's agent dir. |

## Stretch (shadowing) — expected observations
- Authored `omp-course-lab/.omp/skills/<name>/SKILL.md` with a `description:` line (native provider requires it) + restart → `read skill://<name>` returns the authored body.
- `manage_skill create` for the same name → `isError: true`, `details.shadowed = true`, no file written. The previously created managed file (if any) is still on disk but hidden from discovery.
- Delete the authored copy, restart → managed skill resolves again.
