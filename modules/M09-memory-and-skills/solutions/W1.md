# Instructor notes — W0 and W1

## W0 — defaults
Expected shell output on a clean `omp/18.3.1` profile (verified on the build machine):

```
$ omp config get memory.backend ; omp config get autolearn.enabled ; omp config get checkpoint.enabled
off
false
false
```

If a learner sees something else, they have a global override in `~/.omp/agent/config.yml` (from an earlier module or a prior experiment). `omp config reset <key>` removes it. Note that `omp config get` merges the project layer only when run from inside a directory with a non-empty `.omp/` — a learner running it from `$HOME` will see globals only.

`/memory stats` with `off`: the doc says statistics are shown "when supported"; with no backend there is nothing to render. Do not promise exact wording.

## W1 — retain / recall
Grading checklist:
1. `retain` result text is exactly `1 memory stored.` If the learner's model batched two items, `2 memories stored.` is also fine.
2. After `/new`, the answer must come from a `recall` or `reflect` card **in the new session**. If the model answers from the auto-injected `<memories>` block without a tool card, that still demonstrates persistence (auto-recall on first turn) but does not meet the stated pass condition — have them ask "search your memory for DATABASE_URL" to force an explicit `recall`. The fact itself is true of the lab: `tests/support.py` `TempDB` copies `data/lab.sqlite` to a temp file and sets `DATABASE_URL` to it.
3. `read memory://<id>` must show frontmatter with `store: working` (fresh rows stay in working memory until consolidation promotes them; `/memory enqueue` respects a 12-hour age gate, so `store: episodic` on the same day would be surprising) and `memory_type: fact`, `importance: 0.75`, `source: coding-agent-retain`.

Why the outline's `read memory://root` was replaced: `omp://memory.md` states the `memory://root[/…]` rows are file-backed and exist only with `memory.backend: local`; under `mnemopi` they do not resolve. `memory://<id>` is the Mnemopi equivalent. See `BUILD-NOTES.md`.

Common failure: learner changed directory between sessions (e.g. opened omp from `omp-course-lab/api`). `per-project` scoping hashes the absolute cwd, so that is a different bank → `No relevant memories found.` Fix: always start omp from the repo root, or set `mnemopi.scoping: global` for the class.

Backend init failure (`Mnemopi backend is not initialised for this session.`): most often the local embedding model. `mnemopi.noEmbeddings: true` makes W1/S1 pass with FTS matching — the query "tests … database" matches the stored text literally.

Cost note: with `mnemopi.llmMode: smol`, Mnemopi's fact/entity extraction calls the learner's `tiny`→`smol` role; `llmMode: none` avoids that spend entirely and does not affect this exercise.
