# Settings used in the course

Defaults are the *definition defaults* reported by `omp read cfg://<key>` (`default:` line) on the build machine. `omp config get <key>` prints the **effective** value for the cwd — including project overrides — so run it from the repo you care about. Keys are exact schema paths (`omp config list` shows all ~500). ⚠ = off/gated by default and a lesson turns it on.

## Where a value can come from (highest wins)

| Layer | Location | Written by |
|---|---|---|
| declared env var | e.g. `PI_SMOL_MODEL`, `OMP_PROFILE` | shell |
| runtime override | in-memory | `/settings`, `/computer on`, `/advisor on` (session only) |
| overlays | `PI_CONFIG_FILES`, then repeated `omp --config <file>` (launch/`acp`/`models` only) | you |
| project | `<cwd>/.omp/config.yml` (`.omp/` must be non-empty; **no ancestor walk**) | hand-edit |
| global | `~/.omp/agent/config.yml` (`omp config path`; profile → `~/.omp/profiles/<n>/agent/`) | `omp config set/reset`, `/settings` |
| default | definition | — |

Objects merge across layers; **arrays and scalars replace**. `omp config set --json` reports `overriddenBy` when a higher layer wins. Invalid YAML is quarantined as `.broken-<timestamp>-…` and startup fails.

## Commands

```bash
omp config path                     # active agent dir
omp config list [--json]            # every key, effective value
omp config get <key> [--json]       # effective value for this cwd
omp read cfg://<key>                # value + type + default + source
omp config set <key> <value>        # writes GLOBAL config.yml only; --json shows overriddenBy
omp config reset <key>
PI_CONFIG_FILES=ci.yml omp config get tools.approvalMode   # test an overlay
```
